Introduction

This page explains why the Canvas Design Agent exists, what problem it is trying to solve, and what we are doing with it in the workshop.

01

What Is the Point of This?

This tool came out of work I have been doing over the past few years to mitigate a few problems that keep showing up in teaching:

  • Classes are larger.
  • Students have different expectations around Canvas and asynchronous engagement.
  • Attendance, access, and participation do not always look the same as they used to.

I decided to work on this through UX inside Canvas for two main reasons:

  • I am a design person who makes interactive things, so this is the way I know how to solve problems.
  • It is hard to teach the importance of UX and interaction principles through course interfaces that are mostly non-visual.
02

Canvas Is Just Limited HTML

Every page you create in Canvas is made by generating HTML. The page editor lets you work visually, but behind the scenes it is still writing HTML.

  • Open any of your Canvas pages.
  • Press the </> button.
  • You will see the HTML source Canvas is using to render that page.

This also means you can author Canvas pages directly as HTML. That has always been possible; the awkward part is knowing which HTML and CSS Canvas will actually keep.

03

What Is the Catch?

Two things make this trickier than ordinary web design:

  • Canvas limits which HTML elements, CSS properties, and attributes can be used. It strips stylesheets, scripts, and other features for security and platform consistency.
  • The exact practical limits are not always documented in a way that is useful when you are trying to design actual teaching materials.

The result is a strange design space: you can do more than the visual editor suggests, but less than a normal website allows.

04

What Is It?

Over the past year, I packaged the Canvas workflows I have been using into a generic format called a skill. A skill is basically a carefully structured text file that tells an AI coding agent how to work in a specific context.

In this case, the skill tells the agent to generate Canvas-ready HTML using a known set of rules, constraints, and reusable elements.

View the Canvas Design Agent skill on GitHub

What Are We Doing Today?

  • Getting set up with the tools.
  • Learning the basic design process of working from text files to HTML to Canvas pages.
  • Experimenting with the tools using a fictitious course generated for the workshop.

We will use the workshop Canvas course as the place to create and test pages.

07

Caveats

  • This tool is still very much in development.
  • Working with web-based chat is useful for today, but it is not the ideal long-term workflow.
  • Part 2 in the Fall will focus on developing locally with more advanced agent tools.
08

Feedback

If you have comments, questions, or examples of where the tool breaks down, send them along. The point is not to pretend this is finished; the point is to make the workflow visible enough that we can improve it.
